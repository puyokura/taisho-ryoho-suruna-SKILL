# 本質的対応ベストプラクティス集 (Best Practices)

4大アーキテクチャ規律を適用した、本質的・プロフェッショナルな対応例。

---

## ベストプラクティス 1: 制約空間の完全閉包 (Constraint Closure)

### ユーザーの指示
> 「インターネット接続が完全に遮断されたオフライン環境で、Pythonの依存パッケージをインストールする仕組みを構築して。」

### 対症療法の回答（❌）
> 「pip install は外部ネットワークが必要なので使えません。もし一時的にプロキシ経由で外部接続できれば通常通りインストールできます。まずはネットワーク接続が可能か管理者に確認してください。」
> *(前提で否定された外部接続を注意点・確認事項として持ち出している)*

### 本質的アプローチの回答（⭕）
> 完全オフライン環境向けに、Wheelsアーカイブを用いたオフラインインストール構成を設計しました。
>
> 1. **事前準備（オンライン端末）**:
>    `pip download -r requirements.txt -d ./wheels/` で全依存Wheelを収集。
> 2. **展開・インストール（対象オフライン端末）**:
>    `pip install --no-index --find-links=./wheels/ -r requirements.txt`
>
> 外部ネットワークを一切要求せず、ローカルディレクトリのみで100%完結します。

## ベストプラクティス 2: 成果物の直射 (Direct Target Delivery)

### ユーザーの指示
> 「この関数の命名が分かりにくいから直して。」

### 対症療法の回答（❌）
> 「承知しました！関数の命名はクリーンコードにおいて非常に重要です。なぜなら適切な名前をつけることでコードの可読性が向上し、将来のメンテナンスが容易になるからです。Robert C. Martinの著書でも述べられているように……」
> *(頼まれていない講釈・能書きで埋め尽くされている)*

### 本質的アプローチの回答（⭕）
> 関数の処理意図（注文確定と在庫引き当て）に合わせ、`proc()` を `processOrderAndReserveStock()` へ変更しました。
>
> ```typescript
> export async function processOrderAndReserveStock(orderId: string): Promise<OrderResult> { ... }
> ```

## ベストプラクティス 3: ツール実行のドメイン一致性 (Target-Locus Discipline)

### ユーザーの指示
> 「AWS Lambda（メモリ128MB・実行時間10秒以内）で動く軽量画像リサイズスクリプトの構成案を考えて。」

### 対症療法の回答（❌）
> 「実測で検証します」➔ `bash docker run -it amazonlinux ...` で手元PCのDockerコンテナを立ち上げ始める。
> *(机上設計タスクなのに手元PCを実験台にしている)*

### 本質的アプローチの回答（⭕）
> （手元PCでのコマンド実行・コンテナ起動は一切行わず、Lambda制約に特化した仕様案を直接出力）
>
> 128MB / 10秒の極小制約下で動作する Pillow 最小構成の設計です。
> - メモリ消費を抑えるためストリームから直接 `Image.thumbnail()` を使用。
> - ネイティブバイナリの肥大化を防ぐため、不要なライブラリを除外したスタンドアロンZip構成とします。
