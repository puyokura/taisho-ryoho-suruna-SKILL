# taisho-ryoho-suruna-SKILL (対処療法するなSKILL)

> **「直前の失敗単語をそのまま禁止ルールにするな。根本原因を構造的アーキテクチャ規律へ昇華せよ。」**

AIエージェントのプロンプト改変、コード修正、トラブルシューティングにおいて、最も頻発する悪癖である**「対症療法（Symptom Patching）」を根絶するための恒久スキル・行動規範リポジトリ**です。

---

## 1. なぜ「対症療法」は破綻するのか？

多くのAIエージェントは、ユーザーから叱責やバグの指摘を受けると、以下のような「対症療法的パッチ」を生成します：

```text
[ユーザー] 「管理者権限がないって言ってるだろ！WHPXを注意点に出すな！」
  ↓
[AIの対症療法] 「WHPXを注意点に出してはならない。一般権限のときは〜」
  ↓
[次のタスク] 「Dockerが使えない環境で〜」
  ↓
[AIの再発] 「Docker Desktopを起動してください。管理者権限が必要です。」 (また同じミス！)
```

### 対症療法の3大病理
1. **個別固有名詞への依存（Literal Parroting）**:
   WHPX、QEMU、SSH接続先、特定のファイル名など、直前のインシデントの具象単語をそのままルール化するため、別のツール・環境になった瞬間に同じミスを繰り返す。
2. **指示の狭小化とプロンプト肥大化**:
   個別ケースの禁止事項が雪だるま式に増え、プロンプトのコンテキストを圧迫し、指示がコンフリクトしてエージェントの知能を著しく低下させる。
3. **抽象的能書きへの逃避（Abstract Hand-waving）**:
   「対症療法をやめろ」と言われると、具体的なエンジニアリング判断基準（何をブロックし何を削るか）を欠いた抽象論に逃げ、実効性を失う。

## 2. 4大本質的アーキテクチャ規律 (Architectural Invariants)

本スキルは、個別キーワードに一切依存しない、普遍的な**4大構造境界**を定義します：

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 制約空間の完全閉包 (Constraint Closure)                  │
│    制約の外側は存在しない。注意点や代替案としても言及禁止   │
├─────────────────────────────────────────────────────────────┤
│ 2. 成果物の直射 (Direct Target Delivery)                    │
│    指示の動詞と目的語に直結する成果物のみを出力。講釈を全廃 │
├─────────────────────────────────────────────────────────────┤
│ 3. ツール実行のドメイン一致性 (Target-Locus Discipline)      │
│    設計タスクで作業ホストを触るな。手元PCを実験台にするな   │
├─────────────────────────────────────────────────────────────┤
│ 4. 環境文脈の事前解決 (Context Resolution & Hard Stop)      │
│    定義済みの事実を自律解決せよ。毎回言わせるな。即座に止まれ│
└─────────────────────────────────────────────────────────────┘
```
