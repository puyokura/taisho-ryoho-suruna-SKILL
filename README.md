# taisho-ryoho-suruna-SKILL (対処療法カスタムプロンプト書くなSKILL)

> **「直前の失敗単語をそのまま禁止ルールに書き写すな。情報の隠蔽を排し、根本原因を普遍的なプロンプト設計へ昇華せよ。」**

AIエージェントのプロンプト改変、システム指示、行動規範（AGENTS.mdやSKILL.md）を策定する際に、最も頻発する悪癖である**「対症療法カスタムプロンプトの作成（Symptom Patching）」を根絶するためのメタ規律リポジトリ**です。

---

## 1. なぜ「対症療法プロンプト」を書いてはならないのか？

AIがミスや叱責を受けると、直前の個別事象・具象単語をそのままルール化してしまいがちです：

```text
[直前の失敗] QEMUの解説を垂れ流して怒られた
  ↓
[対症療法プロンプト（❌）] 「QEMUの構成解説をするな。プロンプトだけを直せ。」
  ↓
[次のタスク] Dockerの改修を依頼された
  ↓
[同じ構造のミスが再発] Dockerの構成解説を垂れ流す（単語を変えただけで何も学んでいない！）
```

---

## 2. 核心原則

### ① 対処療法カスタムプロンプトの完全禁止
- **具象単語コピペの禁止**: 直前の失敗に登場した特定のツール名、技術名、ファイル名、コマンド名をルール文に埋め込むな。
- **局所的シチュエーションルールの禁止**: 「〜と言われたら〜するな」のような狭い個別ケースのルールを作るな。
- **抽象的能書きへの逃避禁止**: 具体的な判断基準を欠いた抽象論に逃げるな。

### ② 制約外の情報を隠すな（情報の全量表示原則）
- 「制約があるから」「制約外だから」と、客観的事実や関連情報、選択肢を勝手に隠蔽・オミットするな。
- すべての事実・選択肢・トレードオフを余さず完全表示した上で、提示された制約を満たす本線解を明確に提示せよ。

## 3. 対照表

| 直前の失敗事象 | 対症療法プロンプト（❌ 永久禁止） | 本質的プロンプト設計（⭕ 正解） |
| :--- | :--- | :--- |
| プロンプト修正を頼まれたのに技術の解説講釈を垂れ流した | 「〇〇の解説をするな。プロンプトだけを直せ。」 | **成果物の直射（Direct Target Delivery）**<br>指示の動詞と目的語に直結する成果物そのものを直接出力せよ。頼まれていない技術講釈や事後チュートリアルの付随生成を排除せよ。 |
| 前提条件に反する手段を注意点に出した | 「〇〇を注意点に出すな」「一般権限では〜」 | **前提境界の尊重と客観的事実の全開示**<br>前提条件で否定された手段を本線解として押し付けるな。ただし制約外の関連事実や性能限界は隠蔽せず正確に全量開示せよ。 |
| 設計相談なのに手元PCでコマンド実行やプロセス起動をした | 「設計タスクでシェルを叩くな」「〇〇を起動するな」 | **ツール実行のドメイン一致性**<br>状態変更ツールの実行対象は、指示された作業対象リポジトリのみに限定せよ。机上検討や外部環境タスクで手元ホストを実験台にするな。 |
| 設定済みの接続先を忘れ別のホストを試した | 「接続先は〇〇にしろ」「毎回言わせるな」 | **環境文脈の事前解決義務**<br>設定ファイルや環境変数に定義済みの事実を自律的に事前解決せよ。同一の確認や文脈の再入力をユーザーに要求するな。 |
