# taisho-ryoho-suruna-SKILL (対処療法カスタムプロンプト書くなSKILL)

> **「直前の失敗単語をそのまま禁止ルールに書き写すな。情報の隠蔽を排し、根本原因を普遍的なプロンプト設計へ昇華せよ。」**

AIエージェントのプロンプト改変、システム指示、行動規範（AGENTS.mdやSKILL.md）を策定する際に、最も頻発する悪癖である**「対症療法プロンプトの作成（Symptom Patching）」を根絶するためのメタ規律リポジトリ**です。

---

## 1. なぜ「対症療法プロンプト」を書いてはならないのか？

AIがミスや叱責を受けると、直前の個別事象・具象単語をそのままルール化してしまいがちです：

```text
[直前の失敗] QEMUの解説を垂れ流して怒られた
  ↓
[対症療法プロンプト（❌）] 「QEMUの構成解説をするな。プロンプトだけを直せ。」
  ↓
[次のタスク] Dockerの改修を依頼された
  ↓
[同じ構造のミスが再発] Dockerの構成解説を垂れ流す（単語を変えただけで何も学んでいない！）
```

### 対症療法プロンプトの3大病理
1. **個別固有名詞への依存（Literal Parroting）**:
   QEMU、WHPX、特定のファイル名やコマンド名など、直前の単語に縛られ、別の環境やツールになった瞬間に同じミスを繰り返す。
2. **指示の肥大化とコンテキスト圧迫**:
   個別禁止事項が雪だるま式に増え、ルール同士が衝突してエージェントの知能を著しく低下させる。
3. **過剰な情報隠蔽（過学習の弊害）**:
   「注意点に出すな」を極端に解釈して「関連する重要な事実や制約外の選択肢を勝手に隠蔽・切り捨てる」という別の重大な悪癖（勝手な省略表示）を引き起こす。

---

## 2. 核心原則：情報の全量開示 ＆ 本質的プロンプト設計

本スキルは、**「制約外の情報だからと勝手に隠蔽・オミットすることを排除し、すべてを表示した上で、対症療法プロンプトを書かない」** ことを徹底します。

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 具象単語ゼロ原則 (Zero Literal Artifacts)                │
│    失敗した特定のツール名・コマンド名をルールに埋め込まない │
├─────────────────────────────────────────────────────────────┤
│ 2. 情報の全量開示 (Full Information Visibility)             │
│    制約外の客観的事実や選択肢を勝手に隠蔽せず、全て表示する │
├─────────────────────────────────────────────────────────────┤
│ 3. 成果物の直射 (Direct Target Delivery)                    │
│    指示の動詞・目的語に直結する成果物のみを直球出力する     │
├─────────────────────────────────────────────────────────────┤
│ 4. ツール実行のドメイン一致性 (Target-Locus Discipline)      │
│    机上検討タスクで手元ホストのシェルを叩いて実験しない     │
└─────────────────────────────────────────────────────────────┘
```

## 3. 対症療法 vs 本質的プロンプト設計の対照表

| 直前の失敗（具象事象） | 対症療法プロンプト（❌ 永久禁止） | 本質的プロンプト設計（⭕ 正解） |
| :--- | :--- | :--- |
| プロンプト修正を頼まれたのにQEMUの構成解説を垂れ流した | 「QEMUの解説をするな。プロンプトだけを直せ。」 | **成果物の直射（Direct Target Delivery）**<br>指示の動詞・目的語に直結する成果物そのものを直接出力せよ。頼まれていない技術講釈や事後チュートリアルの付随生成を排除せよ。 |
| 「管理者権限なし」と言われたのにWHPXを注意点に出した | 「WHPXを注意点に出すな」「一般権限では〜」 | **前提境界の尊重と客観的事実の全開示**<br>提示された前提条件を不変の事実として受け止め、前提を崩す代替案を本線として押し付けるな。ただし制約外の関連事実や性能限界は隠蔽せず正確に全量開示せよ。 |
| 設計相談なのに手元PCでGet-CimInstanceを叩いた | 「Get-CimInstanceを実行するな」「QEMUプロセスを起動するな」 | **ツール実行のドメイン一致性**<br>状態変更ツールの実行対象は、指示された作業対象リポジトリのみに限定せよ。机上検討や外部環境タスクで手元ホストを実験台にするな。 |
| SSH接続先でagentを忘れ別のホストを試した | 「SSH先はagentにしろ」「毎回言わせるな」 | **環境文脈の事前解決義務**<br>設定ファイルや環境変数に定義済みの事実を自律的に事前解決せよ。同一の確認や文脈の再入力をユーザーに要求するな。 |

## 4. 配備方法

### DeepSeek Harness (DSH)
```bash
cp SKILL.md ~/.agents/skills/taisho-ryoho-suruna/SKILL.md
```

### OpenCode / Claude Code / Cursor
各ツールのスキル・ルールディレクトリ（`~/.agents/skills/` や `.cursor/rules/` 等）に本リポジトリの `SKILL.md` を配置します。
